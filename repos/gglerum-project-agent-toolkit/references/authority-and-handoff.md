# Authority and durable handoffs

Let the consumer define its authority order. Canonical specifications, accepted decisions and executable evidence have distinct roles; agent instructions and generated exports must not silently rewrite product requirements.

Persist current task/scope, accepted decisions, branch/HEAD and dirty work, completed changes, verification commands/outcomes, blockers and the next concrete action. Keep waiting items in one place with their owner rather than duplicating lists in each handoff.

Archive older handoff state separately when the project uses a rolling current record. A historical note is not evidence that the current code or installed runtime still matches it. Recheck actual Git state on resumption.
