# Session review

Write a compact handoff: scope, accepted decisions, branch/HEAD and dirty work, completed changes, exact checks/results, unresolved blockers and the next concrete action. Separate current state from dated history; link durable records rather than duplicating them.

Review repeated corrections, expensive orientation and failed tool assumptions using only the authorized session/project scope. [Session analysis](../../tools/session-analysis/README.md) can measure transcript patterns when transcript access is explicitly in scope. Relative metrics are not currency or proof of better decisions.

Propose changes to guidance, tools or permissions with evidence. Record accepted preferences only; do not automatically rewrite project instructions, enable hooks, read unrelated transcripts or switch the user's model.
