# Origins and manual updates

components.json records each retained component's source project, exact reviewed revision, original path, actual file hash, destination hash and meaningful adaptations. Each tool/skill folder also carries ORIGIN.md and ORIGIN.json; flat references have adjacent origin files. Retain these and included licences when adopting material.

The owner explicitly authorized copying anything useful from the selected ten projects and approved reusable adaptations. This mixed collection does not grant a new blanket licence over third-party content. Installed package licences and source notices remain attached. No original source project is modified by an import.

For an update, select the originating project folders explicitly, compare their recorded files, review changes and dependencies, adapt the useful changes in this independent repository, run its relevant tests and relocation checks, and refresh provenance after review. The origin-drift tool is a read-only comparison aid; no automatic harvest/sync mechanism or remote repository is created.

The inventory ledger records retained material, canonical alternatives, represented mechanisms, withheld requirements and exclusions. A group-level retained result does not promote its excluded or unfinished subcomponents. Source-specific permissions, private data and downloaded reference content are not adoption assets.
